# Jackle 太變態了——七月 AI 小聚全對談心得

> 對談形式：上半場慕約主持，來賓小馮(薩泰爾全端工程師)、Jackle(卡柏蒂資訊長)；下半場 Sunny 主持，來賓 Peggy(NGO行政專員)、海總理(USPACE AI長)。核心比喻：每個人心裡都畫了一條線——AI 做到哪裡、人從哪裡接手，而且這條線一直在動。

---

## 上半場：AI 那邊有多遠

### Jackle：一人軍隊 + 逆向工程一台電話

- **配置**：6 個 Claude Max 帳號 + 1 個 Codex Max 同時跑，Claude 負責分配工作/實作，Codex 做 QA；每天螢幕使用 17-18 小時；睡前交 spec，醒來檢查進度
- **金句**：「假設請一個人六萬塊，我可以買十個帳號。」Fable 出來後直接打消請人念頭——這是他自己畫的那條線因為模型進步而往 AI 那邊挪動的具體案例（Fable 背景見 [[fable-unknowns-thariq-2026-07]]）
- **逆向工程電話案例**：想讓 AI 接打公司電話 → 先自己做偵察：找到 PBX 主機、查出品牌、Google 到操作 PDF、跟通訊處要帳密 → 把帳密+API網址丟給 Claude「把 API 全部逆向拔出來」。**重點：AI 只是最後一步，前面一整輪偵察工作是人做的**，沒有分機架構的公司這招用不上
- **Context 系統**：「無為」自動產會議記錄轉 spec；「大掌櫃」CRM 記錄所有電話/LINE/Email。靠這些 context 算客戶成交率，業務優先打 80%+ 成交率的客戶，期望值直接影響月餅原料採購（要提早2-3個月訂，多買浪費少買賠）
- **誠實的自評**：他覺得自己做到的連 5% 都不到，工廠端沒接進來，最緊急的第一線溝通（例：某批月餅 10% 沒蛋黃，靠電話緊急處理）完全沒被記錄下來
- **AI 不直接賺錢，但讓你比對手快**：喜餅市場十億，卡柏蒂吃一億，效率優勢能往九億推

### 小馮（薩泰爾）：矩陣合併剪片

- 節目用 6 機拍攝，A Cut(篩鏡頭)以前要好幾小時。跟 Google 架構師討論後，把 6 機畫面合併成 2×3 矩陣格式的單一影片，AI 一次看完 6 個角度、時間軸對齊，產出 EDL 轉 XML 直接餵 Final Cut Pro/Premiere
- 毛片剪輯改用 FFmpeg CLI 直接切：4 小時的活壓縮到 23 分鐘
- **矩陣合併這個解法是人想出來的框架，AI 在框架裡做決策**——跟 Jackle 的偵察案例是同一個模式
- 團隊：他一人工程師 + PM Jerry + Sunny。Jerry 已進化到自己拉 Repo、用 Codex 改前端、給小馮 code review——「已經變成一個可以開始寫程式的 PM」
- 分工共識：**程式寫在 Claude Code，非程式需求(發想/故事統整/生圖)用 Codex**

## 下半場：人這邊有多近

### 快問快答（作者自己也回答了）

|------|--------|-------|-------|
| 起床第一件事 | 量體重 | 女兒 | — |
| Agent 叫什麼 | Lora(前執行長秘書名) | R2D2 | Faye |
| 會跟AI聊心事嗎 | 最近會聊女兒行為困擾 | 半年一次(人際支援斷裂時) | — |
| AI 掌握你的 context % | 15%(投影片丟進專案，但高橋流字少) | 10%(只在信任案子錄音) | **70-100%**(寫日記/覆盤情緒/萃取電子報成Skill) |

Sunny 的結論：兩人的 context % 都比她預期低很多——「我們每個人都是一個小宇宙，永遠不會被 AI 取代。」

### 兩個女兒，同一個結論：動機

- **海總理的10歲女兒**：平板被禁 → 給她電腦+Claude試做遊戲 → 1小時做出寶石三消第一版，後來自己加排行榜、朋友來挑戰。她自己想做，爸爸只給工具，這件事她持續在做（跟以前學吉他鋼琴半途而廢完全不同）
- **Peggy的6歲女兒**：3歲起試各種方法讓她接觸AI(GPTs繪本/語音聊天)，直到女兒認真說「媽媽不要再給我什麼臭AI，我要跟你講話」——她要的是陪伴，不是工具。Peggy 後來改策略：不直接給，讓女兒當觀察者，等她自己來要
- **共同結論**：工具是中性的，人不是，動機決定方向

### 由下而上的導入策略（五種做法同一件事）

- **Jackle**：不做POC，直接做「看起來像成品其實是假的」mockup丟給使用者，一小時內就有回報，比需求訪談快
- **Sunny**：讓員工覺得「是自己想到的」，不能說"I told you"
- **海總理**：150人裡找十幾個有動機的人先做出東西，其他人自然有壓力；自己只做不超過50%，讓對方覺得是自己做的
- **Peggy**：陪跑公務員同邏輯，刻意留一個不完美版本讓對方有動手空間。有位公務員三週沒見面後主動回報：自己做了好幾個自動化專案、買了Claude Code帳號，「AI帶給我這陣子很多工作上的熱情」
- **黏土比喻**：乾掉的黏土能不能澆水救回來？Peggy：可以，但需要一個外部的人去點火

跟 [[agent-enablement-patrick-debois-2026-06]] 講的「AI agent 規模化是組織問題不是技術問題」是同一個命題的實戰版——這裡五個人給的具體做法（留50%空間、讓對方覺得是自己想到的、找有動機的人先做），是 Debois 講的抽象組織方法論的操作細節。

### 郭奶奶助理的倫理糾結（全場最有重量的段落）

- Peggy 是「認真的麻瓜」(不會寫程式)，用 Claude Code + OpenClaw 幫全盲、街頭藝人的媽媽做了 LINE 語音AI助理「郭奶奶助理」，能登記表演場地、預約門診、甚至幫 Peggy 女兒網購
- 年會前慕約建議開源，Peggy 準備好了 repo，**最後決定不開源**
- 原因：助理能在復康巴士登記時間一到的瞬間自動搶進去，但復康巴士是稀缺資源、先到先得，其他不會上網的身心障礙者家庭每次要打電話等半小時才排到。「我一直在想這件事情跟黃牛搶演唱會票有什麼差別」
- 沒有給答案，只留下判斷：**AI 可以做到，不代表應該做；但如果你不做，別人遲早會做**——未來 Agent 會變標配，屆時「先到先得」不該是唯一的稀缺資源分配方式

## 結論：你的那條線在哪裡

五個人的線畫在不同地方，且都在移動：

- **Jackle**：線畫在執行那邊，理解判斷留給自己——因 Fable 出現往 AI 那邊挪了一大步
- **小馮**：線畫在 AI 初剪完成之後，最終審片是人的事
- **Peggy**：線畫在「能做」跟「該做」之間，自己還在想；底線持續後退（去年要懂每個程式檔案，現在只要懂系統怎麼運作）
- **海總理**：線畫在效率和體驗之間，學語言這種需要觀言觀色的事AI目前接不住，堅持找真人老師
- **Sunny**：線畫在論述節奏上，AI能翻譯整份簡報，但停頓/加速的節奏必須自己掌握

> 問題不是 AI 能不能做，是你的那條線畫在哪裡——而且要時不時回頭看，那條線是不是已經移動了。

## 對派哥的意義

「逆向工程一台電話」「矩陣合併剪片」兩個案例的共同結構，直接呼應派哥自己的自動化實作模式：**AI 執行的前提永遠是人先把偵察/框架做好**（找到帳密與 API、設計 2×3 矩陣格式），這點在派哥自己 debug cc_processor/investment pipeline 時反覆出現——AI 能查代碼、能改 parser，但「哪個銀行寄信習慣是什麼、帳號遮罩規則有沒有考過真實帳號」這類偵察工作，還是要先由人（或至少人+AI一起）確認過，AI 自己編不出來。

郭奶奶助理的稀缺資源倫理問題，也值得記一筆：派哥自己在幫家人/朋友做自動化（例如訂餐廳、搶票類需求）時，如果哪天也做到「AI幫你搶稀缺資源比別人快」的程度，這篇提出的問題就不再是別人的故事。
